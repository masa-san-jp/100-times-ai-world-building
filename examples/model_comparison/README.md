# モデル比較の作例：サイズの違う 3 モデルで同じ世界を作る

同じ入力・同じ設定・同じ基準で、大きさの違うローカルモデル 3 つに世界設定資料を作らせた結果です。
このハーネスでは、出力の形式（JSON Schema）と採否の基準（`config/world/criteria.yaml` の 9 基準、世界全体の基準 `config/world/world_criteria.yaml`）をリポジトリが決め、どのモデルにも同じものを守らせます。
判定（入力にない現実世界の体系の持ち込み・審査・言い換えの判定）は、生成するモデルに関係なく固定した判定モデルで行います。
そのため、モデルの違いは「動く・動かない」ではなく、**基準を満たして採用された量・掘り下げた深さ・かかった時間** の違いとして表れます。

この作例は閲覧用です。エンジンの仕組み（コード・設定・プロンプト・テスト）からは参照しません。

## 条件

| 項目 | 値 |
|---|---|
| 入力 | [`input/user_input.txt`](qwen3.8_27b/input/user_input.txt)（3 モデル共通、下記の 3 文） |
| 判定モデル | `qwen3.8:27b`（3 実行とも共通） |
| コンテキスト長 | 16384 |
| seed | 1 |
| 実行環境 | Apple M4 Max / メモリ 128 GB、Ollama（ローカル、別プロジェクトと共用） |
| コード | `main` の `34d2a50`（#90 マージ時点） |

入力（作例のために用意した、どの作品にも由来しない 3 文）：

> 塩の採掘で成り立っている内陸の盆地。雨はほとんど降らず、水は地下の古い導水路から引いている。
> 導水路の管理権をめぐって、採掘組合と水番の家系が長く対立している。

## 結果の比較

| モデル | ディスク上のサイズ | 反復 | 採用 | 不採用 | 到達したスケール | 生成の呼び出し | 所要時間 |
|---|---|---|---|---|---|---|---|
| [gemma4:e4b](gemma4_e4b/final/world_bible/README.md) | 9.6 GB | 12 | 6 | 6 | 世界 → 地区 | 222 | 約 2.3 時間 |
| [gpt-oss:20b](gpt-oss_20b/final/world_bible/README.md) | 13 GB | 18 | 13 | 5 | 世界 → 細部 | 429 | 約 8.6 時間 |
| [qwen3.8:27b](qwen3.8_27b/final/world_bible/README.md) | 17 GB | 31 | 28 | 3 | 世界 → 細部 | 653 | 約 8.1 時間 |

- 「採用」は、すべての基準に合格して世界に加わったエンティティの数です。「不採用」は、作り直しの上限内に基準を満たせなかった反復の数です。基準は 3 モデルとも同じで、モデルに合わせて緩めていません。
- 反復の回数がそろっていない理由：12 反復で止める予定でしたが、途中再開（`--choice 2`）で反復の上限が引き継がれませんでした。qwen3.8:27b は世界全体の基準をすべて満たした時点（31 反復）で自動停止し、gpt-oss:20b は 18 反復で止めました。量の比較は、1 反復あたりの採用率（gemma4:e4b 50%、gpt-oss:20b 72%、qwen3.8:27b 90%）で見るのが適切です。
- 所要時間は、3 本を同じマシンで並列に走らせ、別プロジェクトとも Ollama を共用した状態の値です。判定はすべて 1 つの判定モデルに集まるため、単独で走らせた場合より長くなっています。

### 世界全体の基準の達成状況

| 基準 | 閾値 | gemma4:e4b | gpt-oss:20b | qwen3.8:27b |
|---|---|---|---|---|
| 入力への忠実さ（faithful） | 1.0 | ✓ 1.0 | ✓ 1.0 | ✓ 1.0 |
| 広がり：軸の被覆（breadth.axes） | 1.0 | ✗ 0.19 | ✗ 0.38 | ✓ 1.0 |
| 広がり：視点（breadth.perspective） | 1 | ✓ 1 | ✓ 2 | ✓ 6 |
| 深み：関係（depth.relations） | 0.3 | ✓ 0.50 | ✓ 0.57 | ✓ 0.46 |
| 深み：歴史（depth.history） | 1 | ✗ 0 | ✓ 1 | ✓ 2 |
| スケール：世界 / 地域 / 集落 / 地区 | 各 1 | ✓ 2 / 1 / 1 / 2 | ✓ 6 / 1 / 1 / 1 | ✓ 15 / 4 / 1 / 1 |
| スケール：施設 / 細部 | 各 1 | ✗ 0 / 0 | ✓ 1 / 3 | ✓ 3 / 4 |
| スケールの連鎖（世界から細部まで途切れない） | あり | ✗ | ✓ | ✓ |

閾値は暫定値です（`config/world/world_criteria.yaml`）。

### 判定モデルの精度

判定モデル `qwen3.8:27b` は、検証用の事例集（`tests/fixtures/judge_cases/`）で次の精度でした（`scripts/validate_judges.py`）。

- 現実世界の体系の持ち込み（86 事例）：違反の判定の正解率 0.92
- 既存の事実の言い換え（34 事例）：34 件すべて正解

## モデルごとの世界

各モデルは、最初に世界の約束事（契約：暦・技術・社会の枠組み）を入力から 1 項目ずつ決め、その範囲で世界を組み立てます。

### gemma4:e4b（9.6 GB）

- エンティティ：塩盆地・水番家系の水利権主張（世界）→ 塩涸谷（地域）→ 塩の汲み場（集落）→ 塩門の関所・水番血統評議会の監視規定（地区）
- 抜粋（地区「塩門の関所」の数量の事実）：「塩月暦の「水番潮」の基準に基づき、導水路の水位差は「塩水尺」を用いて1の測定値で計測される。」
- 所見：最も小さいモデルでも、契約で決めた暦と単位に沿って、世界から地区まで掘り下げた資料ができます。一方で、軸の被覆と歴史（出来事）はこの反復数では基準に届きませんでした。

### gpt-oss:20b（13 GB）

- エンティティ：塩水盆地・地下水配分証明書・塩源統制集団・古代塩水協定ほか（世界）→ 乾塩渓谷（地域）→ 塩雲集落（集落）→ 塩雲域（地区）→ 塩雲小区（施設）→ 塩雲乾貯・塩雲乾塊・塩霧倉庫（細部）
- 所見：世界から細部まで途切れずに掘り下げ、証明書・協定のような文書や制度も出しました。軸の被覆は基準に届いていません。

### qwen3.8:27b（17 GB）

- エンティティ：塩盆地・水番家系・導水路統制所・導水路管理権世襲規ほか 15 件（世界）→ 塩田区・北塩面・硝塩窪ほか（地域）→ 塩面集落（集落）→ 西側塩面区（地区）→ 西側洗掘面・北側採掘面・洗掘面水圧調整作業組（施設）→ 初代水番水源確保の儀・西側洗掘槽・基準水尺洗掘法ほか（細部）
- 所見：世界全体の基準をすべて満たした唯一のモデルです。場所・制度・出来事・手順をつなげ、儀礼のような歴史の事実まで掘り下げました。

## 読み方と限界

- 入力 1 つ・seed 1 つの結果です。同じモデルでも、入力・seed・反復回数で結果は変わります。
- 反復回数はモデルごとに異なります（上記の理由）。
- 小さいモデル（gemma4:e4b、9.6 GB）でも、形式と基準を守った資料が出ます。モデルの大きさは、量・広がり・深さの差として表れます。

## ファイル構成

各モデルのディレクトリは、`output/world_<run_id>/` と同じ世界パッケージです。

```text
<model>/
├── input/                # 入力の原文と入力ブリーフ
├── world/                # 軸・グラフ・選好ログ（各ステップの試行）
├── checkpoints/          # 途中再開用
├── final/
│   ├── world.json        # 世界モデル（機械可読）
│   ├── world_bible/      # 世界設定資料（README・スケール別・エンティティ別・用語集・年表・世界内文書）
│   └── world_report.md   # 探索の結果（軸の被覆・スケール別件数・ステップ別の試行と不合格理由）
├── quality_report.md
└── run_manifest.json     # 設定・seed・モデル・判定モデル・停止理由・計測
```
